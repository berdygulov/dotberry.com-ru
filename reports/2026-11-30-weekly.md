# Еженедельный отчёт dotberry.com

**Период:** 23.11 – 29.11.2026 (неделя 1, старт проекта)
**Дата отчёта:** 30.11.2026

## Итог недели
Проведён первичный аудит сайта, подготовлен технический SEO-аудит с доказательствами и составлен план продвижения. Работа с сайтом (внедрение правок) ещё не начиналась — нужны доступы и разработчик.

## Что сделано

### 1. Первичный аудит
- Разобран проект: сервис, модель WHOIS/ToS, цены, стек, структура сайта (5 индексируемых страниц) — [OVERVIEW.md](../OVERVIEW.md), [аудит](../audit/2026-11-26-initial-audit.md).
- Зафиксировано, что работает хорошо: HTTPS, canonical, hreflang (en / ru / x-default), SSR, корректный 404, доступность для Googlebot и YandexBot.
- Составлен список проблем и точек роста, список конкурентов и вопросов клиенту.
- Сохранены снапшоты `robots.txt`, `sitemap.xml`, скриншоты PageSpeed Insights.

### 2. Технический SEO-аудит
[TECH-SEO-AUDIT.md](../TECH-SEO-AUDIT.md) — 11 проблем со сводной таблицей приоритетов, у каждой — доказательства и что сделать.
- 🔴 Высокий: автоматический редирект на `/ru/...` по языку браузера со всех EN-страниц; /pricing — зоны подгружаются кнопкой, случайный порядок, дубли.
- 🟠 Средний: ошибки 500 на служебных URL, нет DNS-записи `www`, временные редиректы `/en/*`, ~820 КБ JavaScript.
- 🟡 Низкий: заголовки безопасности, кнопки вместо ссылок, alt, предупреждения в консоли, sitemap.

Уточнения по ходу недели:
- **Скорость (TTFB).** Повторный замер: 0,3–0,45 с при кэше Next.js (норма ≤ 0,8 с). Медленные ответы (~2 с) — когда кэш устарел. Страницы `/domains`, `/pricing`, `/how-it-works` не кэшируются вообще. Задача по кэшу перенесена в этап «Структура» — вместе с шаблоном новых страниц. Данные — [audit/raw/2026-11-26-ttfb-cache.txt](../audit/raw/2026-11-26-ttfb-cache.txt).
- **Кэш.** Проверено: CDN и кэша nginx нет, кэширует только Next.js.
- **Редирект по языку.** Разобрана позиция Google (включая оговорку про `x-default`). Принято решение: убрать редирект со всех URL и заменить баннером выбора языка.

### 3. План продвижения
- [PLAN.md](../PLAN.md) — подробный план по этапам: подготовка, техника, on-page, семантика и структура, контент, внешние факторы, отчётность.
- [PLAN-SHORT.md](../PLAN-SHORT.md) — краткая версия, только общие направления.
- Сроки пересчитаны под режим 1 день в неделю с полным циклом «ТЗ → внедрение → проверка → правки → перепроверка»: основная часть плана — ~6 месяцев.

## Решения
- Редирект по языку браузера — убрать полностью, заменить баннером (решение SEO, без компромиссного варианта).
- Сроки плана — по месяцам, без точных дат.
